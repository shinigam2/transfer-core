# Transfer Core

Сервис ядра международных денежных переводов для тестового задания **«Transfer Core»** (Python 3.12, FastAPI, PostgreSQL 16, `psycopg 3`).

Реализованы уровни **Level 1**, **Level 2** и **Level 3**: расчёт котировок в режимах `SOURCE` и `TARGET`, резервирование средств и суточные лимиты клиентов, отбор и переключение между провайдерами, идемпотентность запросов, приём уведомлений от провайдера (webhook) с проверкой подписи, защита от двойных выплат при обрывах связи, восстановление незавершённых операций после перезапуска и фоновая сверка статусов, а также миграции базы данных.

---

## Быстрый запуск с нуля

Требования: установленные **Docker** и **Docker Compose**.

Запустить базу данных, эмулятор провайдеров (`mock-provider`) и сам сервис одной командой:

```bash
docker compose up --build
```

Для запуска в фоновом режиме:

```bash
docker compose up -d --build
```

После запуска доступны:
- API сервиса — `http://localhost:8080` (проверка работоспособности: `GET http://localhost:8080/health`);
- эмулятор провайдеров — `http://localhost:9000`;
- PostgreSQL — порт `${DB_PORT:-54329}` на хост-машине.

При старте сервис сам применяет SQL-миграции из папки `migrations/`, загружает стартовые балансы клиентов из `data/clients.json` (без дублирования при повторных запусках) и поднимает фоновые потоки отправки и сверки переводов.

Остановить контейнеры и полностью очистить базу данных:

```bash
docker compose down -v
```

## Как запустить тесты

### 1. Одной командой через Docker (основной способ, локальный Python не требуется)

Команда сама поднимет нужные зависимости и выполнит все модульные и интеграционные тесты внутри контейнера:

```bash
docker compose run --rm api pytest -v
```

### 2. Локальный запуск (при запущенной БД в Docker)

```bash
docker compose up -d db
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
DATABASE_URL=postgresql://transfer:transfer@localhost:54329/transfer .venv/bin/pytest -v
```

## Проверка в режиме сбоев (`chaos_run.py`, Level 3)

Скрипт `scripts/chaos_run.py` проверяет работу сервиса под нагрузкой при обрывах соединения, долгих ответах, задержке появления выплаты у провайдера, дублях и нарушении порядка уведомлений, а в конце сверяет наши балансы и статусы с фактическим журналом выплат эмулятора (`admin/ledger`).

1. Перезапустить стенд с эмулятором в режиме `chaos`:

```bash
MOCK_MODE=chaos docker compose up -d --build
```

2. Запустить проверку (локально из виртуального окружения):

```bash
.venv/bin/python scripts/chaos_run.py --transfers 300
```

Либо без локального Python — прямо внутри сети Docker:

```bash
docker compose cp scripts/chaos_run.py api:/tmp/chaos_run.py
docker compose exec api python /tmp/chaos_run.py \
  --transfers 300 \
  --api http://127.0.0.1:8080 \
  --mock http://mock-provider:9000 \
  --data /data
```

Вернуть стенд в обычный режим после проверки:

```bash
docker compose down -v && docker compose up -d
```

## Устройство проекта

```text
app/
  config.py             — чтение настроек из переменных окружения
  db.py                 — пул соединений с PostgreSQL и применение SQL-миграций
  errors.py             — единый формат ошибок API {"error": {"code", "message", "details"}}
  money.py              — работа с деньгами (Decimal), валютами и правилами округления
  reference.py          — загрузка справочников data/*.json (валюты, тарифы, провайдеры, клиенты)
  rates.py              — получение курсов валют, отсев устаревших пар, обратные и составные курсы
  pricing.py            — расчёт котировок в режимах SOURCE и TARGET
  quotes_repo.py        — сохранение и чтение котировок в БД
  balances.py           — резервирование, списание, возврат средств и проверка суточных лимитов
  routing.py            — отбор подходящих провайдеров, проверка маржи и расчёт оценки
  provider_client.py    — HTTP-клиент к эмулятору провайдера и разбор его ответов
  transfers_repo.py     — запросы к БД для переводов, попыток выплат и истории статусов
  transfers_service.py  — проведение перевода, переключение между провайдерами, уведомления и сверка
  main.py               — сборка приложения FastAPI, запуск и корректная остановка фоновых задач
  routers/              — обработчики HTTP-запросов (quotes, transfers, clients, webhooks)
migrations/             — последовательные SQL-миграции схемы PostgreSQL
tests/                  — модульные и интеграционные тесты (Level 1–3)
```

## Методы API

| Запрос | Назначение | Коды ответа |
|---|---|---|
| `POST /quotes` | Рассчитать и сохранить котировку (`SOURCE` или `TARGET`) | `201 Created` |
| `GET /quotes/{quote_id}` | Получить сохранённую котировку (пока не истёк срок её действия) | `200 OK` |
| `POST /transfers` | Создать перевод по котировке (обязателен заголовок `Idempotency-Key`) | `202 Accepted` (в обработке), `200 OK` (повторный запрос по завершённому переводу) |
| `GET /transfers/{transfer_id}` | Текущий статус перевода, история переходов и список попыток у провайдеров | `200 OK` |
| `GET /clients/{client_id}/balance` | Доступный остаток (`available`), сумма в резерве (`reserved`) и списано (`debited`) по валютам | `200 OK` |
| `POST /webhooks/{provider_id}` | Приём уведомлений о статусе выплаты от провайдера (с проверкой `X-Signature`) | `200 OK` |
| `GET /health` | Проверка доступности сервиса и соединения с БД | `200 OK` |

Для проверки отдельных сценариев эмулятора запрос `POST /transfers` также поддерживает необязательный заголовок `X-Scenario` (`ok`, `decline`, `error_5xx`, `slow`), который передаётся провайдеру.

## Коды ошибок

Все ошибки возвращаются в едином виде:

```json
{
  "error": {
    "code": "AMOUNT_BELOW_MIN",
    "message": "Минимальная сумма — 1000.00 RUB",
    "details": {"min": "1000.00"}
  }
}
```

### Обязательные коды из условия

| Код | HTTP | Когда возвращается |
|---|---|---|
| `VALIDATION_ERROR` | `400` / `401` / `404` | Неверный формат JSON или типов полей, неверное число знаков после запятой для валюты, неположительная сумма, отсутствие `Idempotency-Key`, неизвестный клиент или провайдер, неверная подпись `X-Signature` в уведомлении |
| `UNSUPPORTED_DIRECTION` | `422` | Нет тарифа для выбранного сочетания стран, валют и способа выплаты (`payout_method`) |
| `AMOUNT_BELOW_MIN` | `422` | Сумма перевода меньше минимального порога направления (либо не покрывает комиссию) |
| `AMOUNT_ABOVE_MAX` | `422` | Сумма перевода больше максимального порога направления |
| `RATE_UNAVAILABLE` | `422` | Нет подходящего курса, прямой курс устарел или источник курсов недоступен |
| `QUOTE_NOT_FOUND` | `404` | Котировка с указанным `quote_id` не найдена |
| `QUOTE_EXPIRED` | `422` | Срок действия котировки (`expires_at`) истёк |
| `INSUFFICIENT_FUNDS` | `422` | На счёте клиента недостаточно доступных средств (`available`) в валюте списания |
| `DAILY_LIMIT_EXCEEDED` | `422` | Перевод превышает суточный лимит клиента (`daily_limit`) за текущие сутки по UTC |

### Дополнительные коды сервиса

| Код | HTTP | Когда возвращается |
|---|---|---|
| `IDEMPOTENCY_CONFLICT` | `409` | Повторный `POST /transfers` с уже использованным заголовком `Idempotency-Key`, но с другим телом запроса (`quote_id`, `client_id` или `recipient`) |
| `TRANSFER_NOT_FOUND` | `404` | Перевод с указанным `transfer_id` не найден при запросе `GET /transfers/{transfer_id}` |

## Основные переменные окружения

| Переменная | Значение по умолчанию | Описание |
|---|---|---|
| `DATABASE_URL` | `postgresql://transfer:transfer@db:5432/transfer` | Строка подключения к PostgreSQL |
| `MOCK_PROVIDER_URL` | `http://mock-provider:9000` | Адрес эмулятора провайдеров и курсов валют |
| `PROVIDER_WEBHOOK_SECRET` | `local-dev-webhook-secret` | Секретный ключ для проверки подписи `X-Signature` (HMAC-SHA256) |
| `DATA_DIR` | `/data` | Путь к папке со справочниками `*.json` |
| `CALLBACK_BASE_URL` | `http://api:8080` | Адрес нашего сервиса, который передаётся провайдеру в поле `callback_url` |
| `MAX_RATE_AGE_SEC` | `3600` | Допустимый возраст курса валюты в секундах |
| `PROVIDER_TIMEOUT_SEC` | `32.0` | Время ожидания ответа от провайдера в секундах (позволяет дождаться медленного ответа в сценарии `slow`) |
| `RECONCILE_INTERVAL_SEC` | `1.5` | Периодичность запуска фоновой сверки в секундах |
| `MAX_UNCERTAINTY_SEC` | `45.0` | Предельное время ожидания при неизвестном статусе выплаты, после которого перевод помечается как `NEEDS_REVIEW` |
